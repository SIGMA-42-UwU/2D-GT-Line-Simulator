## 介绍

一个**纯 2D、纯前端、零依赖**的「我的世界 · 格雷科技（GregTech）」生产线规划与模拟工具。
比流程图更直观，且包含**模拟/纠错/直观配平**的功能
用菱形接口块（物料源 / 物料汇）和矩形机器搭出产线，拖拽端口连线，工具会自动校验
「输入内容与配方是否完全对应」，并给出理论耗电、理论耗时与物流吞吐模拟。

* 无需编译、无需安装依赖、无需联网：**双击 `index.html` 即可使用**。
* 纯本地：所有数据保存在浏览器 `localStorage`，并可导出为文件在任意设备间搬运。
* 深色工业风主题，工作区为纯 2D 画布（Canvas 2D 手绘，无第三方库）。
* 一键**自动排版**：按「距离输入端的最短连线长度」给节点定出第 N 步，第 N 步排在第 N 列。
* **缓存器（正方形白板）**：只能配输入，输出强制与输入相同，进多少出多少；把它接进环路即可实现
  **循环连接**（两台机器直连成环会报错并提示需要缓存器）。

## 快速开始

1. **双击 `index.html`**（或运行 `打开模拟器.bat`）。
2. 从左侧栏把 **输入端（物料源）**、**机器**、**输出端（物料汇）** 拖到画布上。
   （也可以单击左侧栏条目，会放在视图中央。）
3. 在「物品库」里创建物品（名称 + 固体/流体），然后：
   * 选中**输入端** → 属性面板里选择供料物品、数量、间隔 t；
   * 选中**机器** → 设置名称、耗电量 EU/t、耗时 t，并在「配方」里逐条添加输入口 / 输出口。
4. 从**输出口**拖到**输入口**即可连线（支持一对多、多对一）。连线上的标签显示上游输出口输出的内容。
5. 端口内容与配方不匹配时整条连线会**变红并给出错误文字**。
6. 点工具栏 **▶ 运行模拟**：连线上出现物料圆点，机器底部显示效率条。
7. **💾 保存**写入浏览器本地存储；**⬆ 导出** 生成 `.gtline.json` 文件。
8. 想先看效果：**📂 流程文件 → 导入流程文件 → 选择 `samples/` 下的示例**。

> 如果你的浏览器在 `file://` 协议下禁用了 `localStorage`，界面底部状态栏会提示
> 「本地存储不可用」，此时请用 `本地服务器(可选).bat` 打开，或坚持用「导出」保存文件。

## 核心概念

### 物品（Item）

物品是**白板**：只有 **名称** 与 **属性（固体 / 流体）**，可选备注与颜色。

* 物品库属于**当前流程文件**（随流程一起保存/导出）。
* 配方与接口块通过**物品 id** 引用物品，因此**改名不会断开引用**。
* 固体与流体的区别：图标为实心/空心方块，用于提示物态；同名不同物态视为两个不同物品。

### 机器（Machine）

机器是**白板矩形**，只有四项参数：

| 参数 | 说明 |
| --- | --- |
| 名称 | 自由文本 |
| 耗电量 | 单位 **EU/t** |
| 耗时 | 单位 **tick**，**20 tick = 1 s** |
| 配方 | **手动**添加的有序列表：输入若干条、输出若干条 |

「配方」的顺序**就是端口的顺序**：第 1 条输入 = 机器左侧从上往下第 1 个输入口，
第 2 条输入 = 第 2 个输入口……输出口同理在右侧。机器高度会随端口数量自动增长。
所以**输入/输出口的数量由配方决定**，不需要单独设置。

配方行支持 **↑ / ↓ 重排** 与删除：

* 重排时**连线会跟着配方行一起移动**（连线记住的是「需要某个物品的那个端口」），
  所以重排不会把已有连线改接到别的物品上、也不会突然报错。
* 删除某一行时，会先提示该端口上有几条连线，确认后**这些连线一并移除**，
  其余端口的连线索引自动前移，不会产生悬空指向。

### 缓存器（Buffer）

与机器放在左侧同一栏里的**正方形白板**，用来在产线中做缓冲/中转，尤其是**循环连接**：

| 规则 | 说明 |
| --- | --- |
| 形状 | 正方形（边长随输入条数增长，始终保持 1:1） |
| 输入 | 和机器一样可以**手动配置**：有序的输入列表（物品 + 数量），第 i 条 = 左侧第 i 个输入口 |
| 输出 | **不能单独设置**：输出强制与输入一一对应，第 i 个输出口的内容永远等于第 i 个输入口（属性面板里以只读的「→ 输出口 i」提示） |
| 速率 | **进出速率恒等（严格成立）**：每条通道的总输入速率恰好等于它的总输出速率（缓存器只中转，不改变数量，也不耗电、不耗时）。模拟用 Gauss-Seidel 弛豫把缓存器网络迭代到固定点，因此「进 = 中转 = 出」在展示的数据里精确相等（误差 < 1e-9） |
| 数量 | 输入上的「数量」只用于标识端口内容与显示，缓存器**不限制速率**（不像机器那样按数量/耗时约束供料） |
| 循环 | 把缓存器接进环路即可实现**循环连接**（例如 A → 缓存器 → B → A）；两台机器直连成环仍会报错，并提示需要接入缓存器 |
| 堵塞环 | 若缓存器环内**完全没有出料/消耗端**（环上每个输出口都只有一条连线，环路增益 = 1），数学上不存在稳态：现实中缓存器会装满并堵塞。此时给出**警告**并把整环按 0 流量处理（上游也进不去），画布上显示「堵塞：闭环内没有出料端」 |
| 模拟 | 运行模拟时，缓存器内部画出中转箭头，并显示每条通道的「进 → 出」以及底部「进 = 出」总量 |

> 为什么这样设计：格雷科技里机器之间的闭环必须经过某种缓冲/缓存才能成立（否则物料在无缓冲的环里
> 无法稳定流动）。缓存器就是把这个「经过缓冲的循环」显式建模出来：进出守恒，环内按稳态计算。



* **输入端（物料源）**：菱形，只有 **1 个输出口**。参数：供料物品、每批数量、间隔 tick。
  产出速率 = 每批数量 × 20 ÷ 间隔 tick（个/秒）。
* **输出端（物料汇）**：菱形，只有 **1 个输入口**。可选设置「只接受某物品 / 最小数量」，
  留空表示接受任意物品。

### 连线

* 有**方向**：只能从输出口连到输入口（从输入口反向拖拽也支持，会自动纠正方向），
  连线中点有箭头指示方向。
* **一对多 / 多对一**都允许：一个输出口可以连多个输入口；一个输入口可以接多条连线。
* 连线上的标签显示**上游输出口输出的内容**（物品名 ×数量），模拟运行时还显示实际流量 `/s`。

## 自动排版（按「步数」分列）

点工具栏 **📐 自动排版**（或 `Ctrl+L`、画布空白处右键 →「自动排版（按步数分列）」），
工具会按**「该节点距离输入端的最短连线长度」**算出每个节点的**第 N 步**，然后把第 N 步的节点整体排到第 N 列：

| 规则 | 说明 |
| --- | --- |
| 第 0 步（起点） | 所有**输入端（物料源）**，以及**没有任何上游连线**的节点（例如没有输入配方的自发产出机器——它本身就是物料起点） |
| 第 N 步 | 从任意起点出发，沿「输出口 → 输入口」方向的**最短**连线数（BFS 单位权最短路）。**多条路径取最短**，与需求一致（不是最长路径） |
| 最后一列 | 从任何输入端都**不可达**的节点（例如没有来源的纯环路）会被单独放到最后一列，并在提示条中告知数量 |
| 列内顺序 | 用「相邻列重心（barycenter）」做 4 轮前后扫描排序，尽可能减少连线交叉；同权重时保持原有顺序，**结果稳定可复现** |
| 列位置 | 列宽 = 该列最宽节点，列间距 150px（保证贝塞尔连线有空间）；每列沿同一条水平中线垂直居中，行间距 60px |
| 收尾 | 整体居中到世界原点 → 坐标吸附到 24px 网格 → 自动「适应视图」 |

细节：

* **一次排版 = 一步撤销**，`Ctrl+Z` 可整体还原；排版只改 `x / y`，**绝不动配方、物品与连线数据**。
* 排版后仍可手动拖动微调（网格吸附便于对齐）。
* 选中任意节点时，属性面板标题下方会显示 **「距输入端第 N 步」**，悬停节点也会在提示中显示步数，
  方便核对排版依据。
* 由于第 1 步及以上都建立在第 0 步之上，**没有来源的环路**会被识别为「不可达」而不是参与分层。

`js/graph.js` 中的实现（可单独在 Node 里测试）：

```js
var info = GT.graph.computeLayers(flow);   // { stepOf:{id:步数}, layers:[[id...]], maxStep, unreachable, seeds }
var res  = GT.graph.autoLayout(flow, {     // 直接修改 flow.nodes[*].x / .y
  rowGap: 60, columnGap: 150, sweeps: 4, snap: true, center: true
});                                        // 返回 { moved, columns, maxStep, seeds, unreachable, layers }
```

## 校验规则（会实时重算）

**红色 = 错误（ERROR）**：整条连线变红、端口出现 `!` 角标、机器/菱形出现红色计数角标。

| 规则 | 说明 |
| --- | --- |
| 内容不匹配 | 机器某输入口接入的内容与该输入口配方要求的物品不同 → **整条连线变红**并说明两者名称（含「同名不同物态」提示） |
| 供料不足 | 该输入口实际可获得的速率 < 满速需求（数量 × 20 ÷ 机器耗时）。**与模拟一致**：若上游输出口还接了别的支线，按连线数均分后计算（一对多均分） |
| 未接入 | 配方里有输入口但没有任何连线 |
| 未设置物品 | 配方行或输入端没有选物品 |
| 端口失效 | 指向不存在端口的连线（只可能来自手改文件或旧存档；正常删改配方会自动清理）——导入时直接丢弃该连线并给出修正提示 |
| 环路 | 由强连通分量检测出物料闭环 → 环上连线全部标红（格雷科技里的循环需要缓冲，纯闭环不成立）。**报错信息会保留并提示：若确实需要循环，请在环路中接入「缓存器」**；凡是必须经过缓存器的环路都**不算错误**，只会给出“循环连接成立”的提示 |
| 输出端过滤不符 | 输出端设置了只接受某物品，但接入的内容不是它 |
| 缓存器输入未接线 | 缓存器的某个输入口没有接入任何连线 |
| 缓存器输入内容不匹配 | 接进缓存器输入口的物品与该输入口配置的物品不同（与机器同规则，整条连线变红） |
| 缓存器未配置输入 | 缓存器没有任何输入，输出也就无从镜像 |
| 缓存器闭环堵塞 | 缓存器环里没有出料/消耗端（环路增益 = 1）→ 警告：缓存器会装满堵塞，整环流量按 0 计算 |
| 自环 | 节点连到自己 |

**黄色 = 警告（WARN）**

| 规则 | 说明 |
| --- | --- |
| 供料过量 | 接入速率过剩，多余物料会堆积 |
| 输出口未连接 | 产物无处输出（缓存器的输出口未连接时，会显示「进 X → 出 Y（N 个输出口未接）」） |
| 输入端未接线 | 物料源没有连任何输入口 |
| 输出端不可达 | 接了线但从任何输入端都不可达 |
| 机器无名称 | 便于识别的提示 |

**其它提示（INFO）**：耗电量为 0、配方为空、配方重复物品、节点同名等。

## 模拟算法（▶ 运行模拟）

`js/graph.js` 的 `simulate()` 分两层迭代（外层机器产能、内层缓存器网络），收敛即提前结束：

1. **物料源**速率固定：`数量 × 20 ÷ 间隔tick`（个/秒）。
2. **连线流量** = 上游输出口速率 ÷ 该输出口的下游连线数（**均分**）。多对一则在下游输入口**求和**。
3. **机器加工速率** = `min(自身产能 20÷耗时, 每个输入口 可用速率 ÷ 该口配方数量)`，
   也就是「被最紧缺的输入口限制」，同时不超过自身产能。
4. 机器输出口速率 = 加工速率 × 配方数量，回到第 2 步继续迭代，直到稳定。
5. **缓存器**：输出口速率 = 它对应输入口汇入的速率之和（进出恒等，只做中转）。
   这一层用 **Gauss-Seidel 弛豫**迭代到固定点（就地更新，信息当趟就沿环传播）：
   非堵塞环路的每圈增益 ≤ 1/2，几十趟内收敛到 1e-9，因此「进 = 中转 = 出」严格成立。
   若某个输出口没有接线，则显示为「进 X → 出 Y（N 个输出口未接）」并给出警告。
6. **堵塞环**（环上所有输出口都只有一条连线的纯缓存器环，增益 = 1）：不存在稳态，
   按现实中的堵塞处理——整环流量为 0，并在校验中给出警告。

模型是**单调下降**的（机器初值为满速，每轮只可能被限制得更低），因此天然收敛、不会振荡，
也不会出现负数或 NaN；空配方机器没有输入约束、按自身产能连续产出。
缓存器层若在极端图上未收敛，`simulate()` 会返回 `converged:false` 并给出提示，
不会输出被截断的、可能虚高的速率。

结果展示：连线上的物料圆点速度与流量相关、机器底部效率条（绿=满速 / 黄=受限 / 红=缺料）、
属性面板显示 `实际次/s（上限）` 与**瓶颈输入口**、HUD 显示实际总产出。

> 均分是「理论值」模型：真实游戏中物流会就近分配。刻意保持简单可解释，
> 便于用它判断一条产线在理想配平下的产能与瓶颈。
>
> **校验与模拟使用同一套均分假设**：因此不会出现「界面显示校验通过、但每台机器都在饿死」的
> 自相矛盾结果。一个输出口带 N 条支线时，每条支线只分到 1/N 的流量；如果需求之和超过产出，
> 相关连线会同时报「供料不足」，属性面板与悬停提示会说明「由 N 条连线均分」。

## 本地存储与文件

| 存储键 | 内容 |
| --- | --- |
| `gtline.working.v1` | 当前工作副本（编辑时自动暂存，约 0.7 s 防抖） |
| `gtline.flows.index.v1` | 本地存档索引（名称、时间、节点数、大小） |
| `gtline.flow.v1.<id>` | 每个存档的流程数据 |
| **`gtline.presets.v1`** | **预设库（单独存储，与流程文件完全分离）** |
| `gtline.prefs.v1` | 界面偏好（网格、吸附、模拟速度等） |

文件类型：

* **流程文件** `*.gtline.json`：单个产线（物品 + 节点 + 连线 + 视图）。
* **预设文件** `*.gtpresets.json`：预设库，**所有流程文件共用**。
* **备份文件** `*.json`：`流程文件 → 导出全部备份` 会把所有存档 + 预设库打包，用于换电脑迁移。

### 流程文件格式（简化示意）

```jsonc
{
  "format": "gtline.flow",
  "version": 1,
  "meta": { "id": "flow-…", "name": "我的产线", "note": "", "createdAt": "…", "updatedAt": "…" },
  "view": { "x": -170, "y": 210, "zoom": 0.72 },
  "items": [
    { "id": "item-…", "name": "铁锭", "state": "solid", "color": "#e0a13a", "note": "" }
  ],
  "nodes": [
    {   // 菱形：物料源（1 个输出口）
```

## 预设库

* **没有任何默认预设**：全新环境下预设库是空的，全部由你创建（符合「物品与机器都是白板」的定位）。
* 创建方式：选中节点 → 属性面板 **存为预设**（机器会连同**整份配方**一起保存；多选时可以批量保存）。
* 使用方式：从左侧「预设」栏**拖到画布**，或单击放到视图中央。
  * 机器/接口块预设会直接生成节点；若目标流程缺物品，会**按名称+物态自动补建**物品。
  * 物品预设会把该物品加入当前流程的物品库。
* 因为预设内嵌的是**物品快照**（名称/物态/颜色）而不是 id，所以预设可以跨流程、跨设备使用。
* 预设库有独立的 **导出 / 导入 / 清空 / 重命名 / 删除**：`预设库 → 导出预设文件`。

## 与格雷科技的对应关系与取舍

| 需求 / 游戏行为 | 本工具实现 | 说明 |
| --- | --- | --- |
| 机器有输入总线、输出总线、多个槽位 | 输入口 / 输出口与配方行 **1:1** | 按需求「配方为手动添加，具有顺序，为输入输出口做准备」实现，最直观 |
| 供料不足应停机（而非报错） | 标记为**错误**（红色） | 需求要求「非完全对应时整条连线变红并提示错误」，数量不足也属于不能对应 |
| 供料过量 | 标记为**警告**（黄色） | 不阻塞产线，但会堆积，属于设计问题 |
| 循环物流需要缓冲/缓存 | 检测到**纯闭环**即标红 | 与游戏内「不能无缓存自环」一致 |
| 循环物流需要缓冲/缓存 | **缓存器**：只能配输入，输出强制镜像输入，进出速率恒等；接进环路即可成立 | 纯闭环（不经过缓存器）仍然标红，报错里提示接入缓存器 |
| 管道/总线就近分配物流 | 输出口下游 **均分** | 取理论值，稳定可解释 |
| 机器耗时随配方/电压变化 | 手动填写 tick | 保持白板化，玩家填游戏内实际值 |
| 耗电随电压/超频变化 | 手动填写 EU/t | 同上 |
| 能量网络（发电机、线缆） | 只做**理论最大耗电汇总** | 按需求只要求累加显示；能量网是后续可扩展项 |

## 已知限制与后续可扩展内容

* **没有默认预设 / 没有内置配方库**（刻意如此，因为很多GT包都魔改了自己的配方，内置配方库反而会导致麻烦）：需要自己建物品、建机器、填配方，
  可先用 `samples/示例预设库.gtpresets.json` 作为起点。
* **没有能量网络**：只统计理论最大耗电（所有机器求和），不校验发电与线缆容量。
* **均分模型**：一对多时按连线数均分，不模拟游戏内的「就近/优先」分配与堵塞回压
  （唯一的例外是缓存器堵塞环：这种环会被显式判为堵塞并归零）。
  校验（供料不足/过量）与模拟使用同一套均分假设，因此两者结论始终一致；
  一个源带不动更多机器时会统一报「供料不足」，而不是悄悄显示校验通过。
* **没有多配方机器 / 循环配方**：一台机器一份配方；同一台机器不同配方需要建多个节点。
* **缓存器是理想中转**：不建模容量上限、填充延迟与爆发削峰，只保证「进出速率恒等」这一条不变式
  （再加上「环内无出料端 → 堵塞归零」这一条现实规则）；缓存器不耗电、不耗时。
* **自动排版是分列式**：只按「最短步数」分层并做重心排序，是启发式而非「零交叉」最优布线；
  也没有正交走线（连线始终是贝塞尔曲线），连线很多的图仍可能需要手动微调。
* 可扩展方向：能量网络与电压等级（LV/MV/HV…）、机器超频计算、并行数、多配方切换、
  正交走线与交叉最小化排版、只读分享链接、把模拟结果导出为报表。
* 撤销历史保存在内存中（上限 80 步），刷新页面后从自动暂存的工作副本继续。
